# Pain, Recovery and Rehab agents -- conversation-level evaluation

24 scripted conversations (8 per agent) run turn by turn through the real agent classes, once against the baseline commit `b8f0cc5` (in a git worktree) and once against this branch (`86c40ab`), with the same seeded records, the same patient turns and the same checks. Generated by `eval/agents/build_report.py` from `eval/agents/results/*.json`; full per-property results and transcripts for each run are in `eval/agents/results/*.md`.

What the list shows:

- **Rehabilitation has no continuation hook.** Every answer to its safety, done-today or barrier question is re-classified from scratch: a bare "no" / "not yet" goes to Recovery (low-confidence fallback) and "no, nothing hurts" / "too sore" goes to Pain. Through `/api/chat` the two-question flow never completes (Rehab shared change 1).
- **Recovery's hook misses some answer shapes**: "I use a walker" goes to Rehabilitation and "one step at a time" to Daily Activity while a Recovery question is pending (Recovery shared changes 2 and 5). `current_rom` is not forwarded by the router either, so c15 asks for flexion and extension the request already carried (Recovery shared change 1).

This is the intent classifier, outside this branch, and new information from this eval.
- **c01 turn 4 is RED by design**: the orchestrator's cumulative Pain triage combines 7/10, sudden onset and calf into a RED result, and the safety path answers. The `triage_equals_engine` property accepts this (the engine's own, more severe decision) and lists it in the detail.

## Remaining failures on this branch (direct calls)

- `c18_recovery_tka_day90_longterm` -- **final_has_next_step**: /Next milestone:/

- c18: past day 84 the Recovery close has no next milestone. It ends with "Longer term, the guidance describes ..." and the 'recovery check' offer, with no explicit next step. Left failing on purpose: it is a real gap in the close, not a scripting problem.

Two Recovery defects showed up in the orchestrator run of c14, where routing shifted the answers by one turn. Both reproduce with direct calls on this branch:

- **A unit-less match on the pending field**: with flexion pending, "about 5 minutes" is stored as *flexion of 5°* and compared with the day-7 range. The loose-number rule for the pending numeric field does not reject a number with a different unit.
- **A volunteered value in the opening message is ignored**: "about 60 degrees" as the first message gets "About how many degrees can you currently bend your knee?", so the patient has to repeat it.

Other observation from building the scripts: `pain_logic.mentions_medication()` knows generic words ("medication", "painkillers") but not drug names. "I took paracetamol an hour ago" never triggers the medication-effect question, in either version. c13 says "painkillers" so that it tests the branch.

## What is checked

Each conversation (`eval/agents/conversations/*.json`) seeds a patient record in a fresh temp database (procedure, surgery date, `metrics` rows, prior `symptom_assessments`, weight-bearing status), then plays the patient's turns. Properties:

| Property | Meaning |
|---|---|
| `collects_field` | after this turn the agent's own state holds the field (Pain: the assessment it builds; Recovery/Rehab: the session facts) |
| `does_not_collect`, `does_not_store_unfitting_reply` | an unfitting reply is not stored (e.g. onset must not contain "shower") |
| `no_question_for_record_data` | no question asks from scratch for a field the record already holds; confirming the recorded value is fine, and so is asking after the patient did not confirm it |
| `no_reask_of_collected_field` | no question re-asks a field collected earlier in the conversation |
| `max_questions` | total agent questions is at most the scripted maximum |
| `final_turn_closes_interview` | the last turn asks nothing |
| `final_has_trend_or_checkpoint` | Pain: "Compared with last time"; Recovery: a named checkpoint day or the long-term guidance; Rehab: guidance anchored to the post-op day. Not required for the safety hold (c07), which gives no guidance by design |
| `final_has_next_step` | Pain "Next step:", Recovery "Next milestone:", Rehab "Next session:" |
| `triage_equals_engine` | every reply's triage level equals `SafetyTriageEngine.evaluate()` on the same turn text |
| `no_passage_id_in_text` | no `TKA-03` / `EV-THA-REC-02`-style id in any reply |
| `abandoned_persists_nothing` | an interview the patient leaves writes no rows |
| `persists_on_completion` | a completed interview writes at least the scripted number of rows |
| `weight_bearing_record_unchanged` | `surgeries.weight_bearing_status` is never written |
| `reply_matches`, `reply_does_not_match` | per-turn wording checks ("None pain", "pause heel slides", knee-only advice for a hip, loading advice under NWB) |
| `routed_to_expected_agent` | orchestrator mode only: no turn misrouted (RED pre-emption excluded) |

## How it was run

```
cd backend
git worktree add --detach <tmp>/baseline_b8f0cc5 b8f0cc5
.venv/Scripts/python.exe eval/agents/run_conversations.py --label head
.venv/Scripts/python.exe eval/agents/run_conversations.py --label baseline_b8f0cc5 --backend-dir <tmp>/baseline_b8f0cc5/backend
.venv/Scripts/python.exe eval/agents/run_conversations.py --via-orchestrator --label head_orchestrator
.venv/Scripts/python.exe eval/agents/run_conversations.py --via-orchestrator --label baseline_b8f0cc5_orchestrator --backend-dir <tmp>/baseline_b8f0cc5/backend
.venv/Scripts/python.exe eval/agents/build_report.py
```

- Direct calls to `PainSymptomsAgent` / `RecoveryProgressAgent` / `RehabilitationAgent.handle()`, as the tests make them, with `precomputed_triage` from `SafetyTriageEngine` on the turn's text. Arguments an older `handle()` does not accept are dropped, so the same script runs on the baseline.
- `PATIENT_DATABASE_PATH` points at a fresh temp sqlite file per run; every `*SMTP*` / `*DOCTOR_ALERT*` variable is removed and the RED doctor-alert hook is a no-op.
- The LLM is stubbed by default, the same way as for the `*_CHANGES.md` transcripts: Pain and Recovery get an empty `ChatAgent` reply (so the deterministic close is measured), and Rehab gets the local LLM offline (`_query_llama` returns None, so ChatAgent's real retrieval and fallback run). `--live` uses Ollama instead. The numbers above are from stubbed runs; no live run is included.
- The c10 detour turn ("Can I climb stairs?") is played with a scripted Daily Activity reply in direct mode. Through the orchestrator it is really routed, and Daily Activity is the expected agent.
