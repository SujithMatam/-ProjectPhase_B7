# Intent routing benchmark -- before / after per agent

232 labelled single patient messages (`eval/routing/cases.py`), each scored on `IntentClassifier.classify_detailed()` and, separately, on the orchestrator's final routing (`LAMOrchestrator.process()` for a brand-new patient, `AgentRouter.dispatch` stubbed). 177 cases are *clear*, 55 *debatable* (two or three acceptable agents); 6 are answers to a pending question, which carry no routable signal on their own. Sources: 42 from `test_phase2_intent.py`, 4 from `test_multi_agent_orchestration.py`, 2 from `test_recovery_progress_agent.py`, 10 misroutes from `eval/agents/REPORT.md`, 6 audit sentences, 160 new patient-language openings (20 per agent, Indian-English phrasing and spelling slips) and 8 intake guards. Generated by `eval/routing/build_report.py` from `eval/routing/results/*.json`; every case, score and decision path is in `eval/routing/results/<label>.md`.

A prediction is correct when it is in the case's acceptable set. Two cases that the orchestrator must pre-empt (emergency, out of scope) are excluded from the per-agent tables and reported separately. Orchestrator *lenient* counts a turn as routed correctly when at least one dispatched agent is acceptable (the `eval/agents` definition); *strict* requires every dispatched agent to be acceptable.

## What changed in `lam/intent_classifier.py`

Step A (the three requested changes):

1. **Whole-word matching in the medication follow-up check.** `_looks_like_medication_follow_up()` used `marker in text` for both the current turn and the history; it now uses `\b...\b`, with the plural forms ("doses", "tablets", "pills", "medicines", "antibiotics", "painkillers") added so nothing that matched legitimately before stops matching. The keyword rules themselves already used word boundaries.
2. **`I am` / `I'm` is no longer an introduction by itself.** `_is_introduction()` now requires an intake cue: a greeting (whole message, or leading "Hi, ..."), "my name is", one of the `_INTAKE_PATTERNS` (with "I had ... replacement / arthroplasty / operation" added next to "I had ... surgery"), or a capitalised word right after "I am" / "I'm" in the original message that is not a common sentence word ("I am Rishi" yes, "I am Fine" no). The symptom / question override is unchanged.
3. **"safe", "safety", "schedule", "timing", "warning" removed from `_MEDICATION_KEYWORDS`.** "purpose" and "precaution" are of the same kind but no benchmark case touches them, so they were left.

Step B (one more change, same spirit, measured separately):

4. **No semantic INTAKE_CONTEXT without an intake cue.** In `classify_detailed()`, after the semantic scores are computed and before ranking, intake is dropped from the candidates unless `_has_intake_cue()` holds. The keyword-vs-semantic order and both thresholds are untouched.

Also tried and reverted: adding the word forms "paining", "pains", "aches" to the pain keywords. It changed no case on this set ("My knee is paining alot since morning" is already recovered by step B: with intake out of the ranking the Pain prototype wins the margin), so it is not shipped.

## Orchestrator routing versus the classifier

The orchestrator reaches a different answer from the bare classifier in three ways, all outside `intent_classifier.py`:

- **Multi-agent turns** (30 cases): `detect_applicable_intents()` collects every keyword domain in the message and `MultiAgentCoordinator` runs all of them, so "Is drinking coconut water good for recovery?" is answered by Nutrition *and* Recovery. Lenient scoring counts these as correct; strict scoring is where the Nutrition and Wound Care columns lose points.
- **Pre-empted turns** (3 cases): the RED safety path and the ScopeValidator run before routing. "I can't breathe and my knee wound is worse" and "What is the weather like today?" are the intended cases; "On the other hand my knee feels better" is deflected as out of scope because `ScopeValidator` reads "hand" as an unsupported body region (`lam/scope_validator.py`, `_UNSUPPORTED_REGION_LIST`).
- **Patient record and wound context** (1 case): the default patient record lists Paracetamol and Enoxaparin, so any message naming them is MEDICATION before the classifier runs (this is why c13's opening "My knee aches a little, I took paracetamol an hour ago." stays with Medication through the orchestrator), and an explicit wound word gives Wound Care priority over a Pain keyword ("soreness and some fluid leaking near my stitches").

Noticed while reading the orchestrator, not changed (outside the scope of this task): `_has_explicit_different_domain()` in `lam/orchestrator.py` uses substring matching, so the Rehab term "rom" matches "from" ("fluid coming from my incision") and the term "bath" matches "bathroom"; a Pain or Recovery follow-up answer that contains "from" is treated as an explicit topic switch and loses its continuation.

## How to run

```
cd backend
.venv/Scripts/python.exe eval/routing/run_routing_benchmark.py --label <name>
.venv/Scripts/python.exe eval/routing/run_routing_benchmark.py --label semantic_first --semantic-first
.venv/Scripts/python.exe eval/routing/build_report.py
```

Each run writes `eval/routing/results/<label>.json` and `.md` (per-agent tables, misses grouped by rule, the orchestrator-versus-classifier differences, and every case with its scores) and copies the markdown to `eval/reports/<date>_routing-<label>.md`. The runner isolates itself the same way as `eval/agents`: fresh temp database, SMTP* / DOCTOR_ALERT* cleared, the RED alert hook a no-op, `AgentRouter.dispatch` stubbed so no agent or LLM runs.
