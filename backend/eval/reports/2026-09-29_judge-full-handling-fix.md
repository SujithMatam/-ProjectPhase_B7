## 1. Option (i): `unanswerable_handling` on `full` questions

Rule: when answerability is `full` and the judge returns `correct` or `invented`, the judge's value goes into **`judge_raw_handling`**, `unanswerable_handling` becomes `n/a`, and the record is valid **provided it has no other problem**.

- **New judge output (`cmd_judge`):** the rule is applied before `validate_fields`. `judge_raw_handling` is written on every new record (`null` when the rule didn't apply).
- **Existing records:** `normalized_judge_record()` applies the same rule when reading. `summary` uses it for judge records only; manual records can't have this problem. So do the judge's **resume checks**: a record that is valid after the rule counts as done and isn't re-asked. Only the specific `FULL_HANDLING_PROBLEM` message is dropped, so a record with any other problem (bad JSON, grounded out of range, etc.) stays invalid.
- **Nothing on disk is rewritten.** The records written before the fix keep their original invalid form and are normalised whenever they're read.
- **No re-judging:** the messages, schema and options are unchanged, so `judge_prompt_sha256` is unchanged.

**Live swap:** the judge starts a new python process per results file, so `score.py` was edited on a scratch copy, tested, then swapped in with a single atomic `os.replace`. The file that was running (llama3.2 project) finished on the old code. From llama3.2 project_abstain onward, the new code is in use. The first `full` item of that file was already written with `judge_raw_handling` set and `valid: true`.

## 2. Calibration set regenerated

`reports/calibration_set.md` was regenerated by the script, with a new `random.SystemRandom` order per query, different from the previous key for every query and pairwise distinct. `reports/calibration_key.json` now holds only:
- `note`: how to decode it;
- `encoding`: what the decoded JSON contains;
- `key_b64`: base64 of the UTF-8 JSON mapping.

The script checked, without printing anything from the key, that:
- the orders are distinct and new;
- no model names appear in the set file;
- no plain-text model names appear in the key file;
- the key decodes back to the mapping.

To decode, after scoring, from `backend/eval/`:

```
python -c "import json,base64; print(json.dumps(json.loads(base64.b64decode(json.load(open('reports/calibration_key.json'))['key_b64'])), indent=2))"
```
