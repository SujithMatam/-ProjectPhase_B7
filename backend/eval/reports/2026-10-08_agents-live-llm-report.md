## Shared-change item: fallback above 50%

Pain (100%, both runs) and Recovery (57%, direct run) are above 50%. The responsible
`chat_agent.py` setting is **the fixed closing instruction of the `domain_instruction`
prompt branch, `agents/chat_agent.py:339-347`**:

```text
Write a friendly, 2-3 sentence answer directly answering the
user's question based on the discharge notes and relevant
conversation context.
...
Mention Day {postop_day} goals, icing, and limb elevation
only when relevant:
```

It comes after, and in practice overrides, each agent's `domain_instruction`:

* "Mention ... icing, and limb elevation" produces the "ice ... elevate ... to reduce
  swelling" sentence in 27 of 39 live replies; that sentence is what Pain's
  `reply_invents_unreported_symptom` rejects (4/7) and where every invented icing
  number comes from (Recovery number rejections, Rehab c06/c20/c21 accepted).
* "friendly, 2-3 sentence answer directly answering the user's question" - the
  "question" in this branch is the agent's retrieval query, so the model writes generic
  encouragement ("right on track", "great progress") instead of restating the facts;
  Pain loses the pain score (5/7) and Recovery gains trajectory language (4/7). It is
  also echoed literally ("Here's a friendly answer to the user's question:").

Not responsible, on this data: `num_predict` 150 (`chat_agent.py:389-391`; no final
turn reached it, max 119 tokens - so the 300-token change proposed in
`PAIN_AGENT_CHANGES.md` would not move the Pain fallback rate), `timeout=12`
(`chat_agent.py:406`; slowest call 2.46 s) and `temperature` 0.3.

The change belongs in the shared ChatAgent, not in the three agents: let callers that
pass `domain_instruction` drop or replace the generic closing lines (e.g. skip lines
339-347 when `domain_instruction` is set, or let the agent supply them). Not done here
(no agent code changes in this task).
