## What changed and how it showed up in this run

* **Rehab number guard** (`rehab_agent.reply_unsourced_numbers`). An LLM reply is rejected
  when it names a number - digits, number words ("ten", "twenty-five", "twice"), or either end
  of a range such as "15-20" - that is not in the retrieved context, the patient's message,
  the record values the agent passed in (ROM, exercise log, pain, request fields, the
  patient's own barrier words) or the post-op day. The retrieved passages are re-read (same
  query, procedure and limit as ChatAgent, kept to the topics it reported) only when the cheap
  sources do not cover a number; if that lookup fails, the number counts as unsourced.
  Rejected -> sourced fallback.
  * First-run fixtures: c06 (`15`, `3`), c20 (`10`, `15`, `3`) and c21 (`15`, `20`, `3`) are
    rejected (`test_rehabilitation_agent.py` section 21, with the retrieved passages from
    those prompts).
  * This run: **c21 rejected** for `6` in "For exercises weeks 2-6" -> sourced fallback, and
    the `final_has_trend_or_checkpoint` property now passes (277 -> 278). No accepted Rehab
    reply in this run contains a number other than the post-op day.
  * **Flag:** "weeks 2-6" is not invented by the model - it comes from the agent's own
    retrieval query (`_phase_hint`: "weeks 2-6 strengthening"), which echoes the title of
    EV-TKA-REHAB-04. The query is not one of the four allowed sources, so the guard rejects it
    as specified. If you want that range allowed, the clean fix is to drop numbers from the
    phase hint (or add the hint to the sources); I left it strict.
* **Rehab status guard false positive.** A loading phrase is no longer a breach when a
  negator ("not", "never", "avoid", "don't", "without", "rather than", "instead of", ...)
  governs it in the same clause (up to three words before it, with no "when"/"then"/"until"
  etc. in between). Wording that turns the negation back into permission stays a breach: "no
  need to avoid squats", "no reason you can't squat", "don't worry when you bear weight",
  "you don't have to avoid squats".
  * The false positive in LIVE_REPORT was **c24** (NWB), not c21 - c21's status was UNKNOWN,
    which the guard does not check. The c24 reply ("Since you're not allowed to bear weight
    ... it's best to avoid squats") is now accepted, as a fixture and end to end through the
    agent.
  * This run: **c24 still falls back**, for a different reply. "focus on strengthening
    exercises first, rather than doing squats" is negated (that is why "rather than" was
    added), but the closing clause "we can discuss squats further as you progress" names
    squats without a negation, so the guard stays conservative and rejects it. The patient got
    the abstention plus "non-weight-bearing" close. I did not widen the guard to deferrals
    like "discuss ... later".
* **Recovery prompt echo** (`recovery_integration.strip_prompt_boilerplate`). Lead-ins ("Here's
  a friendly answer to the user's question:", "Here is a friendly...", "Here's a friendly,
  2-3 sentence answer directly answering the user's question:"), "Answer:" labels and any line
  restating the instruction wording are removed, along with quotes around the whole answer.
  The acceptance check judges the stripped text. If nothing is left, the reply is rejected and
  the deterministic block goes alone. Fixtures: c04 and c19, both runs
  (`test_recovery_progress_agent.py` section 33).
  * This run: 6 of the 7 Recovery replies opened with the echo. The one accepted reply (c16,
    "Here's a friendly, 2-3 sentence answer directly answering the user's question:") reached
    the patient starting at "It sounds like you're making great progress...". No sent reply
    contains the echo.

## Shared-change item: fallback above 50% (from the first live run, unchanged)

Carried over from the first report; this task did not touch `chat_agent.py`. In this re-run Pain (100%) and Recovery (86%) are still above 50% for the same reasons.

Pain (100%, both runs) and Recovery (57%, direct run) are above 50%. The responsible
`chat_agent.py` setting is **the fixed closing instruction of the `domain_instruction`
prompt branch, `agents/chat_agent.py:339-347`**:

```text
Write a friendly, 2-3 sentence answer directly answering the
user's question based on the discharge notes and relevant
conversation context.
...
Mention Day {postop_day} goals, icing, and limb elevation
only when relevant:
```

It comes after, and in practice overrides, each agent's `domain_instruction`:

* "Mention ... icing, and limb elevation" produces the "ice ... elevate ... to reduce
  swelling" sentence in 27 of 39 live replies; that sentence is what Pain's
  `reply_invents_unreported_symptom` rejects (4/7) and where every invented icing
  number comes from (Recovery number rejections, Rehab c06/c20/c21 accepted).
* "friendly, 2-3 sentence answer directly answering the user's question" - the
  "question" in this branch is the agent's retrieval query, so the model writes generic
  encouragement ("right on track", "great progress") instead of restating the facts;
  Pain loses the pain score (5/7) and Recovery gains trajectory language (4/7). It is
  also echoed literally ("Here's a friendly answer to the user's question:").

Not responsible, on this data: `num_predict` 150 (`chat_agent.py:389-391`; no final
turn reached it, max 119 tokens - so the 300-token change proposed in
`PAIN_AGENT_CHANGES.md` would not move the Pain fallback rate), `timeout=12`
(`chat_agent.py:406`; slowest call 2.46 s) and `temperature` 0.3.

The change belongs in the shared ChatAgent, not in the three agents: let callers that
pass `domain_instruction` drop or replace the generic closing lines (e.g. skip lines
339-347 when `domain_instruction` is set, or let the agent supply them). Not done here
(no agent code changes in this task).
