# Rehabilitation & Exercise Agent — memory-aware, safety-first rework

Branch `feature/agents-proactive`. "Before" is `4d90557` (the Recovery rework;
the Rehabilitation agent itself was unchanged since the baseline in
`AGENTS_BASELINE.md`: single-shot, no questions, no state, nothing read from
the database). Every transcript below was generated by running the real
agent against an isolated temp database with the local LLM **offline**
(`ChatAgent._query_llama` returns `None`), so ChatAgent's real RAG retrieval
and its real generic fallback run exactly as in an offline deployment. The
"before" transcripts use the `RehabilitationAgent` class as it was at
`4d90557`, loaded from git; the "after" transcripts use `agents/rehab_agent.py`.

Scope that was changed: the `RehabilitationAgent` class (moved to the new
`agents/rehab_agent.py`; `agents/specialized_agents.py` re-exports it, so
`agent_router.py` is unchanged), the new `agents/rehab_state.py`,
`agents/patient_memory.py` (extended) and `test_rehabilitation_agent.py`.
Nothing else was edited: not the orchestrator, triage, `chat_agent.py`,
`agent_router.py`, the database schema, the coordinator, or any other agent
class. No new data file was needed: the fallbacks live in `rehab_agent.py`
as a table whose entries cite their passage id in a code comment.

**Safety rule kept:** the LLM never sets or lowers the triage level. Every
reply (ask turns, the safety hold, the answer) copies `precomputed_triage`;
the LLM text, when accepted, only ever sits above the deterministic close.

## 1. What changed and why

### 1a. Memory before asking (`agents/patient_memory.py`, extended)

`load_patient_memory()` already read `surgeries.weight_bearing_status`, the
last 7 days of `metrics` and the procedure. The Rehabilitation agent now
uses them, through new helpers:

- `normalize_weight_bearing_status()` maps the recorded wording (*"Weight
  Bearing as Tolerated (WBAT)"*, *"non-weight-bearing"*, the request enum)
  to `NWB` / `PWB` / `WBAT` / `FWB` and returns `None` for anything
  ambiguous -- never guessed; `PatientMemory.weight_bearing_code`;
- `exercise_log()` / `missed_exercise_days()` / `exercise_log_summary()`
  over the last 7 days' `exercise_completed`; `today_exercise_completed`;
- `rom_summary()` (*"flexion 80° (yesterday), extension 5° (yesterday)"*)
  and `pain_summary()` (*"pain 4/10 (yesterday)"*) from the last 7 days;
- `note_today()` keeps the cached snapshot in step with a value the agent
  has just written.

Precedence is **record first, request as override**: the request's
`weight_bearing_status` replaces the recorded status (*"from this request"*
vs *"on record"* in the instruction and the close), `current_rom` replaces
the logged ROM line, `exercise_history` replaces the logged exercise
summary. Memory is loaded once per 30-minute session and cached on the
state.

### 1b. State machine (`agents/rehab_state.py`, pain_state pattern)

`RehabSessionState`: one pending question, ask counts, the facts the agent
establishes (`exercises_done_today`, `exercise_safety` + the exercise and
kind named, `weight_bearing_status` **as the patient stated it, session
only**, `exercise_barrier`), the topic of the current question, whether it
was direct, a per-question budget counter, the "missed-days opener offered"
flag and the cached memory. 30-minute `INTERVIEW_TTL`, 500-entry cap,
per-instance `RLock`, `get_or_create_state` / `peek_state` /
`_clear_all_state_for_tests` -- the same contract as `pain_state.py`.

Questions (`rehab_agent.QUESTIONS` / `ALT_QUESTIONS`):

| Field | Question | Second ask (after an uncertain or unfitting reply) |
|---|---|---|
| `exercise_safety` | Does any exercise cause sharp pain, or swelling that lasts into the next day? | ... a simple yes or no is fine. Is any exercise leaving you with sharp pain, or a joint that is still more swollen the next morning? |
| `exercises_done_today` | Have you done today's exercises yet? | ... Have you got through today's exercises? |
| `weight_bearing_status` | What weight-bearing status has your team given you -- non-weight-bearing, partial, as tolerated, or full? | ... Did your team say no weight, partial weight, as much as you can tolerate, or full weight through the leg? |
| `exercise_barrier` (opener) | Your log shows exercises missed on N of the last 7 days; anything making them hard? | -- |

Budget per exercise question: **two** for a general question ("what
exercises should I do"), **one** for a direct question that names an
exercise ("how do I do heel slides"). Priority: the missed-days opener
(once per session, when the log shows 2+ missed days in the last 7) →
safety → done-today (general questions only; skipped when today's log
already says yes) → weight-bearing status (only when unknown from record
and request, only for a loading topic or a general question, asked at most
twice). A field is asked at most twice; the second miss records
`"unknown"` and the interview moves on. Answers already known are never
re-asked within the session, so a second question in the same session is
answered at once.

Multi-slot extraction reuses `pain_logic`'s yes/no, uncertainty,
negation-aware keyword (`_keyword_or_negative`) and off-topic-question
helpers: *"I did them this morning and nothing hurts, no sharp pain"* fills
both answers in one turn. A reply that does not fit the pending question
(*"Can I shower tomorrow?"*) is never stored; the question is asked once
more, then left unknown. Volunteered swelling counts as a safety report
only with a "lasts into the next day" cue; when the safety question is
pending any clear yes/no counts. A patient-stated weight-bearing status is
kept in the session only -- `surgeries` is never written (test 13).

### 1c. Answer construction

- **RAG query** (`build_retrieval_query`) from procedure + post-op day + the
  exercise or activity named: *"How should I approach stairs on post-op day
  5 after Total Knee Arthroplasty (TKA)? stairs walking aid walking first
  week"*. The raw patient message travels fenced in the domain instruction
  (test 15 injects an instruction into it and checks it never reaches the
  query).
- **Domain instruction** (`build_domain_instruction`): the Rehabilitation
  focus, the existing untrusted-data framing, the explicit rule *"never
  suggest loading or activity beyond the stated weight-bearing status"*
  naming the status and its origin (or, when unknown, *"do not suggest any
  increase in loading, and ask the patient to confirm their status"*), the
  Pain agent's abstention sentence verbatim, a no-re-triage sentence, and a
  fenced `REHAB CHECK` block with the two answers, the status, the barrier
  and the record lines (ROM, exercise log, latest pain score).
- **LLM reply guard:** the reply is used only when the engine is the local
  model (`Local LLM ...`), it is not the shared generic text, and it does
  not breach the status (`reply_breaches_weight_bearing`: e.g. *"put
  weight"* / *"squat"* under NWB). Otherwise the sourced fallback answers.
- **Procedure-aware fallbacks** (`FALLBACKS`, replacing the shared knee-only
  text that used to reach hip patients): seven entries built only from
  `eval/eval_corpus.json` passages `EV-TKA-REHAB-01/03/04/05` and
  `EV-THA-REHAB-01/03/05`, each with its day window, the topics it can
  answer, tagged steps and a next-session line. `select_fallback()` prefers
  the entry whose window contains the day, else the nearest window; a topic
  no allowed passage covers (THA stairs, squats, swimming, GEN) gets an
  abstention (*"I don't have discharge guidance on stairs for day 20 after
  your hip replacement, so please check with your surgeon or
  physiotherapist"*). Test 16 checks every entry's passage id against the
  corpus and that every number in the steps and next-session lines is one
  the cited passage states (digits and number words). The passage id is in
  the code comment and in `sources`, never in the text.
- **Close**, on every answer: the weight-bearing line in plain words, a
  pause reminder when a concern was reported earlier in the session, the
  barrier if one was given, then exactly one *"Next session: ..."* line
  (from the matched entry, or the abstention's "keep to what your
  physiotherapist set") and *"Say 'rehab check' tomorrow and I'll see how it
  went."* ("rehab check" classifies as `rehabilitation`; test 19.)

### 1d. Proactive behaviour

- **Missed-days opener:** with `exercise_completed = 0` on two or more of the
  last 7 days the first reply is *"Your log shows exercises missed on 3 of
  the last 7 days; anything making them hard?"*; the answer is fed into the
  instruction and the close (*"You said "..." is making the exercises hard
  -- tell your physiotherapist so the programme can be adjusted."*), once
  per session.
- **Persistence when reported:** *"I did them this morning"* /
  *"haven't done them yet"* writes today's `metrics.exercise_completed`
  (1 / 0) the moment it is said, via `patient_memory.write_today_metrics()`;
  nothing else is written.
- **Safety hold:** a report of sharp pain or next-day swelling from an
  exercise gets a deterministic reply with no LLM call: *"Please pause heel
  slides for now and tell your physiotherapist about the sharp pain before
  your next session ... Next session: wait for your physiotherapist's advice
  before repeating heel slides. Say 'rehab check' tomorrow..."*. The
  upstream triage level is carried unchanged (YELLOW stays YELLOW, GREEN
  stays GREEN), the text never reassures (`contains_reassurance` guard,
  test 18), and later answers in the session keep that exercise paused and
  tell the LLM so.

## 2. Example conversations

### TKA, post-op day 5, asking about stairs

Patient on record: `weight_bearing_status` = *"Weight Bearing as Tolerated
(WBAT)"*; yesterday's `metrics` row has `exercise_completed = 1`,
`rom_flexion = 75`, `pain_score = 4`. Triage for every turn: GREEN. Local
LLM offline.

#### Before

**Patient:** Can I go up and down the stairs yet?

> Go up stairs leading with your non-operated leg, then bring your operated leg and any walking aid up to meet it -- "up with the good, down with the bad." Coming down, lead with your operated leg and walking aid first. Always use the handrail and go at a slow, steady pace, and follow your prescribed weight-bearing status.

**Patient:** no, nothing sharp

> Hello! On Day 5 of your recovery from Total Knee Arthroplasty (TKA) (Right), make sure to keep up with your daily physical therapy routine, elevate your leg when resting, and stay hydrated.

(Nothing was read from the record: the recorded weight-bearing status is
not named, no safety question is asked, and the follow-up gets the shared
generic greeting. Engine `Clinical Synthesis Engine`, sources `[]`.)

#### After

**Patient:** Can I go up and down the stairs yet?

> Before I answer: Does any exercise cause sharp pain, or swelling that lasts into the next day? (last question)

**Patient:** no, nothing sharp

> Here's the discharge guidance I have for stairs on day 5 after your knee replacement:
> • For stairs, remember 'up with the good, down with the bad': going up, lead with the non-operated leg; coming down, lead with the operated leg, taking one step at a time and using the handrail.
> • Most people practise climbing up and down two or three stairs with their aid before going home; stepping foot over foot on stairs usually comes later, once walking is normal and the knee is strong.
> • Your physiotherapist will tell you when to change aids and when you are ready to use stairs normally.
>
> Your weight-bearing status on record is weight-bearing as tolerated, so nothing here should take you beyond it.
>
> Next session: a short walk with your aid, then two or three stairs up and down with the handrail, one step at a time. Say 'rehab check' tomorrow and I'll see how it went.

(metadata only); triage GREEN. The direct question took exactly one
question. The instruction sent to the (offline) LLM carried the status
*"WBAT (on record)"*, *"exercises done today: unknown (not asked)"* (today's
log has no row; yesterday's says done), *"sharp pain or next-day swelling

**Patient:** the evenings are too sore to face them

> Thanks -- that helps me understand what's making them hard. Does any exercise cause sharp pain, or swelling that lasts into the next day? (last question)

> Here's the discharge guidance I have for your exercises on day 20 after your hip replacement:
> • Do standing exercises while holding on to something firm and stable, such as a sturdy chair, a bar or a wall, so you are well supported.
> • Standing knee raises: lift the operated leg towards your chest, but not higher than your waist, hold for two or three counts and lower it again.
> • Standing hip abduction: with the hip, knee and foot pointing straight forward and your body upright, lift the leg out to the side with the knee straight, then slowly lower it so the foot is back on the floor.
> • Standing hip extension: slowly lift the operated leg backwards while keeping your back straight, hold for two or three counts, and return.
> • Each is usually repeated about ten times in three or four sessions a day; keep every movement slow and controlled rather than swinging the leg.
> • As strength improves, your physiotherapist may add resistance using elastic tubing, bringing the leg forward, out to the side and backwards against the band; these exercises help your balance and walking.
> • Continue to follow your hip precautions while exercising -- keep the knee below waist height during knee raises -- and stop and tell your physiotherapist if an exercise causes sharp pain in the hip or groin, or if you feel unsteady doing it.
>
> I don't have your weight-bearing status, so don't put more weight through the leg than your team has told you until they confirm it.
>
> You said "the evenings are too sore to face them" is making the exercises hard -- tell your physiotherapist so the programme can be adjusted.
>
> Next session: the three standing exercises (knee raises, hip abduction, hip extension), about ten times each, holding on to something firm. Say 'rehab check' tomorrow and I'll see how it went.

## 3. Shared changes needed (outside this branch's scope)

1. **`lam/orchestrator.py` — a Rehabilitation continuation hook.** The
   orchestrator has continuation checks for Pain, Wound and Recovery only.
   After the Rehabilitation agent asks its safety question, a bare *"no"*
   is re-classified from scratch (observed: `recovery_progress` via the
   low-confidence fallback) and *"no, nothing hurts"* goes to Pain, so the
   answer never reaches this agent through `/api/chat`. A peek-only check
   on `rehab_state.peek_state(patient_id).pending_field` (plus a yes/no or
   weight-bearing-shaped reply), placed where `check_recovery_continuation`
   runs, would route it. Until then the two-question flow works for direct
   callers and tests only; the single-turn behaviour (status from the
   record, sourced fallbacks, the close) works through the orchestrator
   already.
2. **`agents/chat_agent.py` — the generic exercise fallback.** `
   _generate_smart_reply()` still carries the knee-only exercise text
   (*"heel slides aiming for 70°–90° flexion ... walking 5–10 minutes with
   your walker every 2 hours"*) and the *"Swelling ... is normal"* line.
   This agent no longer lets them through (it uses an LLM reply only from
   the `Local LLM` engine), but any other caller of `ChatAgent` still gets
   them; the branch could defer to the procedure-aware table in
   `rehab_agent.FALLBACKS` or be removed.
3. **`agents/chat_agent.py` — token budget** (same item as the Pain and
   Recovery reworks): `answer_question(..., max_tokens=None)` would let the
   answer turn ask for a short reply explicitly.
4. **`patient_database.py` — a first-class metrics upsert.**
   `patient_memory.write_today_metrics()` is now used by three agents and
   still writes the `metrics` table with its own SQL through
   `connection_scope()`; an `upsert_daily_metrics()` helper there would be
   the proper home.
5. **Intent classifier:** the check-in offer depends on "rehab check" being
   classified as `rehabilitation` (verified by test 19 via the "rehab"
   keyword); keep "rehab" in that set if the classifier is retuned. Note
   that "What hip exercises are safe for me?" is classified `medication`
   first ("safe"), so the coordinator runs Medication before Rehabilitation
   for it.
6. **`surgeries.weight_bearing_status` is free text.** Seeded values such
   as *"Weight Bearing as Tolerated (WBAT)"* are normalised by
   `patient_memory.normalize_weight_bearing_status()`; a controlled column
   value (the four codes) would remove the mapping. A patient-stated status
   is deliberately never written there by this agent.
7. **Flutter client / `ChatRequest`:** `exercise_history` and `current_rom`
   are now overrides over the record; the client could stop re-sending
   values the backend already logs.
